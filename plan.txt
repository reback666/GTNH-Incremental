GTNH 增量游戏设计规划书 v2.1

基于 GTNH（GregTech: New Horizons）电压体系，融合产线拓扑、平行宇宙转生、风险-回报杠杆与数值压缩四大核心系统，设计一款面向 GTNH 玩家、一个游戏内周通关 ULV→MAX、完全免费的增量小游戏。离线收益暂缓实现但预留接口。

---

一、项目概述

· 类型：增量 / 放置 / 工厂规划
· 题材：GTNH 格雷科技电力文明
· 目标：从超低压（ULV）起步，最终达到最大电压（MAX）
· 节奏：首次通关约一个游戏内周（7 个游戏内日）。计时以游戏内日为准，与玩家实际在线时长解耦
· 受众：GTNH 玩家，保留核心机制但适度简化
· 商业模式：完全免费，无内购，无付费墙，自愿捐赠
· 核心特色：产线拓扑规划 + 平行宇宙转生 + 风险杠杆决策 + 数值压缩节奏

---

二、核心概念与电压体系

玩家扮演一名工程师，从零开始点亮整个格雷科技的电力文明。核心循环：

规划拓扑 → 启动产线 → 风险决策 → 撞上硬墙 → 突破/转生 → 新周目

电压等级

共 14 个等级，每个等级电压为前一级的 4 倍：

ULV → LV → MV → HV → EV → IV → LuV → ZPM → UV → UHV → UEV → UIV → UXV → MAX

核心机制

· 超频（Overclocking）：机器可消耗更多电力加速运行，分 4 个档位（0-3 档）。
· 并联：同一产线上布置多台同类机器分摊产能，属于拓扑层面的设计（见第四章）。
· 并行（Parallel）：单台高电压机器同时处理多个配方。
· 拓扑（Topology）：机器通过虚拟管道连接，形成产线网络。

注意：并联（多台机器，拓扑层面）与并行（单台机器多配方）是两个不同机制，读音相同但含义不同。

四、产线拓扑系统

核心概念：从“购买机器”到“设计工厂”

元素 设计 与 GTNH 的对应
节点 发电机、加工机器、存储仓、售货机 单方块/多方块机器
边（连接） 虚拟管道，需消耗“线缆”资源建立 管道/线缆/总线
瓶颈 节点有输入/输出速率上限，超过则堵塞 机器处理速度、管道带宽
拓扑优化 并联机器分流、串联加工 产线设计

关键机制

· 动态瓶颈可视化：UI 上堵塞的管道变红，下游机器显示“等待输入”。玩家需要决定是“升级单台机器”还是“并联多台”。
· 产线模板：可保存 3 个“产线模板”，新周目一键导入。

与风险杠杆的结合点

· 超频档位：作用于单个节点，提高档位加速运行，但增加“故障率”。故障会通过拓扑影响相邻节点。
· 污染扩散：污染沿拓扑传播，高污染节点可能“感染”相邻节点。

五、平行宇宙转生系统

核心概念：转生不是重置，而是“分叉时间线”

转生触发：达到 MAX 或满足特定“时空裂缝”条件（硬墙，需研究数据与拓扑复杂度达标）。

转生货币：时空线缆。

平行宇宙选择（每次转生可选 1 个，可叠加）

宇宙 核心机制 对玩法的影响 解锁的专属内容
工业宇宙 量子纠缠：允许跨电压合成（2 LV → 1 MV） 打破电压硬墙，但需要精确计算产线比例 “量子组装机”蓝图
奥术宇宙 Vis 替代：机器消耗 Vis 而非 EU，产量减半但无故障 完全改变资源管理逻辑，适合“稳态流”玩家 “神秘注魔台”蓝图
深渊宇宙 污染即燃料：污染越高，产出越高，但会腐蚀节点 高风险高回报，需要建造“腐蚀抑制器”防止产线崩溃 “深渊熔炉”蓝图
硅基宇宙 自动化觉醒：解锁“自动拓扑优化”AI，可自动调整产线 减少手动操作，适合后期挂机，但 AI 有 5% 的“误判率” “神经网络核心”蓝图

跨周目继承

· 蓝图继承：转生前解锁的蓝图，在新周目可直接用（但需重新建造）。
· 拓扑模板：可保存 3 个“产线模板”，新周目一键导入。
· 宇宙叠加：每次转生选择的宇宙会叠加，形成独特组合（如“工业+深渊”= 高污染下的跨电压合成）。

转生公式

时空线缆 = floor( log₂(总累计EU / 1e12) ) × (1 + 0.1 × 最高电压等级) + (2x + 1)

· x = 已完成转生次数。首次转生 x = 0，保底获得 1 条时空线缆，避免收益为零。
· 第一次转生可在 EV 或 IV 触发，而非等到 MAX，保证前期反馈。
· 转生加成应改变核心缩放公式，而非仅固定数值。

六、风险-回报杠杆

核心原则：玩家主动选择风险，而非被动承受惩罚

三大杠杆

1. 超频档位（离散风险）

· 范围：0-3 档，对应速度 100% / 160% / 220% / 280%，耗电量与速度成正相关。
· 风险：每提高一档，故障率指数上升，档位越高增长越快。
· 故障表现：停机，需要手动进行维护，维护之后恢复正常。
· 自动化：在解锁“自动维护仓”之后，解锁自动维护功能。
· 保留理由：故障是玩家主动提高档位换来的代价，不是系统被动施加的惩罚，因此保留
· 决策：是稳定在 160% 长期运行，还是赌一把 280% 快速突破瓶颈？

2. 污染利用（环境风险）

· 污染值：0-100%。
· <30%：无影响。
· 30-70%：产出 -20%，但随机节点可能“变异”（产出稀有组件、彩蛋物品，但效率不稳定）。
· >70%：产出 -40%，每 10 分钟有 10% 概率触发“工厂崩溃”（随机摧毁一个节点）。
· 净化器：可以降低污染。
· 开关：设置中可整体关闭污染机制，关闭后污染值不增长且不产生任何影响，默认开启。

3. 电网模式（系统风险）

· 稳定电网：EU 消耗 +20%，无故障。
· 波动电网：EU 消耗 -30%，但每 5 分钟有 15% 概率断电 10 秒（产线停滞）。
· 黑市电网：EU 消耗 -50%，但会随机“窃取”你 1% 的 GT 币（作为电费）。

与产线拓扑的结合

· 风险会沿拓扑传播。一个超频 220% 的节点会影响相邻节点，提高它们的故障率。
· 玩家可以设计“隔离区”——用存储仓将高风险节点隔离开。

七、货币体系

采用 双轨核心货币 + 三类辅助资源 体系。

核心货币一：电力（EU/t）—— 你的“时间”

· 定位：流量资源，体现“当前每秒发多少电”，不是可以直接囤积的余额
· 获取：手动点击手摇发电机起步，逐步自动化
· 消耗：每台运行机器持续消耗 EU/t
· 平衡约束：发电量不足以覆盖全部机器的消耗时，部分机器停机
· 存电：中期解锁存电装置后，富余电力可存入电池，形成可囤积的存量；存量耗尽同样导致停机
· 特点：发电量越多 → 机器越多 → 产能越高 → 发电量更多

核心货币二：GT币（Credit）—— 你的“钱”

· 定位：硬货币，用于购买机器蓝图、升级、解锁电压
· 获取：出售产物给自动售货机
· 硬币体系：铜币→白铜币→银币→金币→铂币→锇币→硅岩币→中子素币，8 合 1 自动向上合成
· 消耗：购买机器、解锁多方块、升级超频/并行

辅助资源：机器组件

· 电动马达、电路板、泵、传送带等
· 作为中期瓶颈资源，是解锁机器建造的前置条件
· 由更低级材料和 GT 币合成，形成产业链纵向深度

辅助资源：研究数据（Research Data）

· 通过完成特定里程碑获得（如首次达到 HV、首次建造集成矿石处理厂）
· 用于解锁关键机器蓝图
· 不可重复获取，确保里程碑感

转生货币：时空线缆（Space-Time Cables）

· 达到 MAX 后“科技重生”获得
· 用于购买永久性全局加成
· 加成示例：机器速度 +10%、GT币获取 +25%、初始电力产能 ×2

货币关系图

```
电力（EU/t） ──维持──> 机器运转 ──产出──> 中间产物
    ↑                                          │
    │                                          ↓
 升级/超频 <──消耗── GT币 <──出售── 自动售货机
    ↑                     ↑
    │                     │
 研究数据 ──解锁──> 多方块蓝图 ──需要──> 机器组件

达到MAX后：科技重生 ──> 时空线缆 ──> 永久加成
```

八、数值与平衡公式

成本公式

机器成本 = 基础成本 × 4^(电压等级 - 1) × 1.07^(已购买数量)

· 4^ 来自 GTNH 电压 4 倍递增
· 1.07^ 为边际成本递增，防止无脑堆同一台机器。第 100 台的成本约为第 1 台的 868 倍，单价递增强度仍能压制无脑堆叠，又不会掐死并联路线

产出公式

基础产出 = 基础值 × 4^(电压等级 - 1) × 超频倍率 × 并行倍率

· 超频倍率 = 1 + 0.6 × 超频档位（档位 0-3），能耗 = 2^超频档位
· 并行倍率 = 电压等级 - 配方等级 + 1，仅当电压 ≥ 配方等级时生效

数值压缩

· 显示压缩：EU/t 显示为 1.2 kEU, 3.4 MEU, 5.6 GEU
· 内部计算：统一使用任意精度十进制（后文记作 Decimal），Java 下是 BigDecimal，JS 下是 decimal.js。定长十进制一律不可用：.NET decimal 上限 7.9e28，IEEE decimal128 上限约 1e6144，SQL DECIMAL(38,s) 上限 1e38
· 精度设置：显式指定 40 位有效位数，禁止依赖默认值（decimal.js 默认 20 位，多层 Mod 倍率叠加后会漂）
· 对数运算：转生公式需要 log₂。Java 的 BigDecimal 没有内置 log，需自行实现或引入第三方库；decimal.js 自带。选平台时必须一并确认
· 增长控制：后期成本增长从 4^n 调整为 4^n * log(n)，防止数值爆炸失去意义

硬墙设计

· 电压解锁：不仅需要 GT 币，还需要“研究数据” + “拓扑复杂度”（产线节点数达到阈值）。
· 配方解锁：某些高级配方需要特定宇宙（如“量子组装机”只能在工业宇宙解锁）。

当前版本的“伪离线”处理

· 玩家关闭游戏时，保存拓扑快照和时间戳。

未来扩展点

主界面五区

· 顶部：当前电压等级、EU/t、GT币余额、时空线缆数
· 中部：拓扑编辑器（拖拽节点、连接管道）

· 底部：科技树、商店、转生、设置按钮
· 右侧：类似 NEI 的配方查询面板，可折叠

风险面板

· 超频档位（每个节点独立）
· 污染条（全局 + 节点级）
· 电网模式切换

大数字显示

· 内部计算：统一使用 Decimal（任意精度十进制），避免玩家自制内容堆量后的数值溢出。
· 显示层：
  · 数值 < 1000：显示普通数字，如 856。
  · 数值 1000 ≤ 数值 ≤ 1e18：使用后缀 K、M、G、T、P、E，保留 3 位有效数字。
        例如：1.23K、4.56M、7.89G、1.23T、4.56P、7.89E。
  · 数值 > 1e18：切换为科学计数法，如 1.23e19。
· 可切换：玩家可在设置中切换为“纯科学计数法”或“完整数字显示”。

· 电压突破：Minecraft 烟花特效 + 烟花爆炸音效
· 机器运行：粒子效果，超频时颜色变化
· 转生：时间倒流特效
· 堵塞管道：变红闪烁
· 污染传播：绿色粒子沿管道扩散

十二、挑战与难度机制

· 污染机制：沿拓扑传播，过高降低效率，需建造净化器
· 电力故障：EU/t 不足时部分机器随机停机，需手动重启或投资发电
· 配方复杂度：高电压机器需要更多组件，形成产业链瓶颈
· 随机事件：偶尔出现“矿脉发现”，短时间内产出翻倍
· 拓扑复杂度门控：硬墙要求产线节点数达到阈值

注意：挑战机制应可选，设置“普通模式”和“专家模式”。

十三、音效与氛围

十五、自定义内容接口（Mod 系统）

设计目标

· 让玩家像使用 GTNH 整合包一样，自由添加机器、电压、机制
· 内置内容与自定义内容使用同一套数据格式
· 支持导入导出，方便分享与协作

数据结构（JSON Schema）

所有游戏内容用 JSON 定义，分为五个顶层对象：

电压定义

```json
{
  "id": "custom_voltage_1",
  "name": "自定义电压",
  "tier": 15,
  "voltage": 4,
  "color": "#FF00FF",
  "prerequisite": "MAX",
  "unlockCost": { "credit": "1000000000000000", "research": 100 }
}
```

机器定义

```json
{
```

编辑器 UI

· 入口：主界面“设置”→“内容编辑器”
· 界面：左侧列表（电压/机器/组件/机制/宇宙），右侧表单
· 表单模式：下拉选择、数值输入、颜色选择器
· JSON 模式：高级玩家可直接编辑原始 JSON
· 实时预览：编辑后立即在沙盒中测试
· 校验：检查前置依赖、数值范围、ID 冲突

导入导出

· 导出：生成 .gtnhmod 文件（JSON 压缩包）
· 导入：拖拽文件或粘贴分享码
· 分享码：Base64 压缩字符串，可发在论坛/QQ群
· Mod 管理：启用/禁用/排序，冲突检测

兼容性

· 自定义电压可插入现有电压链，prerequisite 指定前置
· 自定义机器可引用内置或自定义组件
· 自定义机制通过钩子影响核心循环
· 自定义宇宙可叠加到现有宇宙系统
· 版本迁移：Mod 文件带版本号，游戏更新时自动适配
· 大数表示：JSON 中所有 credit / EU 类数值以字符串存储（如 "1000000000000000"）。JS 的 JSON.parse 只有 double 一种数字类型，超过 2^53 时在解析阶段就已丢失原始数字，事后转 Decimal 无法还原

备份

· 备份：导入前自动备份当前存档。

十七、一周通关节奏与调整

节奏以游戏内日计时：游戏内一周（7 日）对应约 80-100 小时等效游玩时间，换算下来一个游戏内日约等于 11-14 小时等效游玩量。目标是在游戏内第 7 日结束前达成 MAX。现实中的分摊节奏由玩家自行决定，不参与进度判定。

游戏内日 电压阶段 关键解锁 玩家主要操作
第1游戏日 ULV → LV → MV 手摇发电机、基础泵、基础采矿机、自动售货机 点击起步，建立第一条自动产线，出售产物换 GT 币
第2游戏日 HV → EV 工业电解机、大型啤酒酿造室、电动马达/电路板产线 建造首个多方块，学习超频与并行，管理污染
第3游戏日 IV → LuV 集成矿石处理厂、研究数据系统、拓扑编辑器 解锁 NEI 配方查询，批量购买机器，优化产线
第4游戏日 ZPM → UV 高级组件（传感器、发射器）、污染净化器 处理产业链瓶颈，投资转生前永久升级
第5游戏日 UHV → UEV 大型加工厂、并行规模化、自动升级 挂机为主，上线收菜，调整超频策略
第6游戏日 UIV → UXV 普朗克电路前置、终极多方块 冲刺终极机器，完成研究数据里程碑
第7游戏日 MAX 普朗克电路、科技重生 达成 MAX，解锁转生，获得时空线缆

每个电压阶段都有明确的“研究数据”里程碑，完成后给予一次性奖励，并解锁下一个电压蓝图。

十八、保留与简化清单

保留的 GTNH 核心机制

· 电压等级 4 倍递增（ULV→MAX 共 14 级）
· 机器组件产业链（电动马达、电路板、泵、传送带等）
· 多方块机器（工业电解机、集成矿石处理厂、大型加工厂）
· 超频与并行
· 污染系统（简化版）
· NEI 配方查询与用途查询
· 任务书/研究数据里程碑

简化部分（让大部分玩家能通关）

· 取消手动摆方块：机器以图标形式在 UI 中购买和升级，无需搭建多方块结构
· 自动合成：组件可一键合成，材料足够即可
· 减少中间产物种类：将数十种电路板简化为每电压 2-3 种关键组件
· 自动出售：可设置自动出售低于当前电压的产物
· 批量购买：支持 ×1、×10、×100、最大
· 污染简化：相对 GTNH 大幅简化，并可在设置中整体关闭
· 无死亡惩罚：机器不会爆炸，只会停机

新增的深度机制

· 产线拓扑：拖拽节点、连接管道、管理瓶颈
· 风险杠杆：超频档位、污染利用、电网选择
· 平行宇宙：转生后选择宇宙，叠加机制
· 硬墙：以研究数据与拓扑复杂度门控电压解锁，控制节奏

---

十九、免费模式设计

· 完全免费，无内购，无付费墙：所有内容通过游戏内进度解锁
· 捐赠：自愿捐赠，捐赠者获得装饰性称号或机器皮肤，不影响平衡
· 无体力/能量限制：玩家可以一直玩，增量游戏的爽感不能被打断

二十、开发计划表

第零阶段：TypeScript 与前端上手（2-4 周）

· 用一个周末小项目练手，覆盖 async/await、DOM 事件、Vite 构建
· 不系统学，够用即开工

第一阶段：核心原型（1-2 个月）

· 实现从 ULV 到 LV 的完整循环
· 基础点击与自动生产（ULV）
· 建立电压等级数据结构（ULV-MAX）
· 实现 LV 单方块机器（基础泵、采矿机）
· 设计初始 UI 与科技树界面
· 拓扑系统 MVP：3 种节点（发电机、加工机、售货机）+ 1 种连接（管道）
· 核心公式：成本 = 基础成本 × 4^(电压等级)，产出 = 基础产出 × 4^(电压等级)

第二阶段：自动化与深度（3-5 个月）

· 扩展至 MV-HV，引入多方块机器
· 实现多方块机器建造与合成（工业电解机）
· 设计“超频”与“并行”机制
· 加入“机器组件”作为关键合成材料
· 风险杠杆原型：超频档位 + 简单故障率计算
· 数值模拟：用 Python 模拟 ULV 到 LV 的通关耗时曲线
· 平衡各电压等级生产效率与资源需求

第三阶段：终局与转生（6-8 个月）

· 解锁至 MAX，实现转生系统
· 填充 EV 至 UXV 的机器内容
· 实现 MAX 等级的“普朗克电路”等终极物品
· 平行宇宙系统：4 个宇宙 + 叠加机制
· 硬墙系统：研究数据与拓扑复杂度门控
· 设计“科技重生”转生系统及永久加成
· 加入成就系统与数据统计

第四阶段：打磨与发布（9-10 个月）

· 基于反馈调整数值曲线
· 优化 UI/UX，特别是拓扑编辑器与风险面板
· 加入音效与粒子特效，增强反馈感
· 数值压缩：Decimal 内部计算 + 显示层压缩
· 准备分享用的入口页面与宣传素材

第五阶段：自定义内容接口（11-12 个月）

· 设计 JSON Schema 与数据加载系统
· 实现内置内容编辑器 UI
· 实现导入导出
