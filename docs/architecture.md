# 项目架构与界面约束

## 模块边界

| 层 | 入口 | 职责 |
| --- | --- | --- |
| 内容 | `src/content/` | 电压、资源、机型与模板的 JSON 定义；注册器检查引用并生成运行目录 |
| 数值 | `src/numeric/` | 纯公式、大数运算、数值格式化；不读取 Vue、存档或浏览器状态 |
| 玩法 | `src/game/core.ts` | 持有游戏进度，执行建造、研究、转生与单步结算 |
| 奥术实体 | `src/game/arcane-expedition.ts` | 节点、调查、培养队列、研究、随机状态与图鉴；通过核心提供的上下文付款和查询工业电压 |
| 核心实例 | `src/game/engine.ts` | 当前唯一的 `GameCore`；读档和重置整体替换 |
| 时间推进 | `src/game/runtime.ts` | 墙钟计时、逐秒推进、长时间补算分片与取消；不依赖 Pinia |
| 存档 | `src/game/save.ts` | 序列化、版本清洗、本地读取与导入；资源数量存十进制字符串 |
| 日志 | `src/game/log.ts`、`diagnostics.ts` | 有界事件留存、筛选、异常现场与用户主动导出的诊断报告 |
| 呈现 | `src/game/presentation/` | 从核心生成只读快照；按设备、资源、进度、宇宙与厂区分模块 |
| 操作协调 | `src/game/store.ts` | 玩家操作入口、模拟调度、存档生命周期与反馈；不写数值展示公式 |
| 视觉场景 | `src/scene/` | Three.js 厂区、相机与采矿反馈；只消费快照，不修改游戏进度 |
| 页面 | `src/components/*Workspace.vue`、`RebirthPage.vue` | 工厂、科技、星图与设置；`App.vue` 只协调导航、页面缓存、主题和启动/销毁 |
| 样式 | `src/styles/` | `tokens.css` 主题、`base.css` 基础元素、`components.css` 功能组件、`workspace.css` 页面与场景 |
| 隔离预览 | `demo.html` | 直接运行现有 `src/main.ts` 与应用，复用 dev 的核心、store、页面、公式和保存；入口仅隔离本地存储，范围见 `status.md` |

`presentation/snapshot.ts` 只组装数据。各子模块不得反向导入 store；场景不得读取可变的核心实例。
快照整体替换并通过 `markRaw` 跳过深层代理，内部字段不能由组件直接修改。
星图目录、挑战选项、转生履历与成就列表按实际输入缓存，输入未变时复用只读对象；线缆、节点、宇宙、挑战、履历、成就或数字显示模式改变时更新对应结果。缓存按核心实例弱引用隔离，读档、重置与新周目不会继承旧核心的结果。转生效果合计按节点列表内容缓存，购买和撤销立即生效。
设备种类的显示顺序和说明以 `presentation/catalog.ts` 为准，操作按 `models.ts` 导出的完整机型目录查找，目录由内容注册器生成。
自定义字段、稳定标识与扩展操作见 `custom-content.md`。

## 数据流

```text
玩家操作 → store → GameCore → 呈现快照 → Vue 控件 / 3D 厂区
实际经过时间 → ElapsedClock → store → advanceSimulation → GameCore.tick
GameCore → 序列化 → 浏览器本地存储 / 用户主动导出的 JSON
```

资源结算顺序仍由 `GameCore.tick` 控制；不能把耗电、燃料、生产等顺序依赖改成任意事件订阅。
音效、日志与粒子属于反馈，不参与资源计算；场景动画使用独立时钟。

## 时间与生命周期

- 在线读取真实经过时间，不假设浏览器定时器每次都准时执行。
- 在线与离线都按一秒推进，最后不足一秒的部分按实际余数结算。离线时长上限由 `runtime.ts` 定义。
- 离线沿用默认 24 小时及原星图加成，`GameCore.offlineCapSeconds()` 再受 runtime 的 72 小时硬上限约束；不能以硬上限替换原星图成长。
- 补算按执行时间分片并让出线程，界面显示进度；不能用后台停止运行的 `requestAnimationFrame` 等待补算。
- 补算期间不叠加在线结算，也不开放进度修改控件。重置、导入、卸载会取消旧补算。
- 补算中途存档使用已完成的时间点，避免刷新或关页后丢掉尚未补算的时间。
- `store.stop()` 清理模拟/存档定时器、浏览器事件和状态订阅；重复启动不累积监听。

逐秒补算比大步近似更耗时，但燃料耗尽、储能、随机事件和研究完成的口径可与在线一致。
优化补算时必须保留这一约束，不能只为加速把一小时当作一拍结算。

## 奥术与风险结算

- 新实体节点增加实时灵气来源，保留原灵气节点机型、源质库存 / 消耗、魔法发电机、魔法机基础参数和宇宙激活规则；不增加可消费钱包。新设施以 `paymentTier` 结算原分级币，工业宇宙的跨级付款继续生效，退款使用显式接口。
- 每拍先 `prepare` 撤下真正开工作业的节点，再计算网络、工业供需和灵气分配；最后按电网实际供电比例推进调查、培养和魔导研究。设施耗电进入原研究类调度，不能绕过供电不足或硅基停机。
- 新节点输出加在原节点的源质折减之后，不额外消耗源质。六要素、节点类型效果只从已安装且非处理中的实体计算；快照和各机型展示共用一次网络，避免千节点重复扫描。
- 灵气按高、中、低优先级分配，同档按需求比例；实际已分配量先从余量扣除，再求各自比例。受矿石、电力等瓶颈限制的灵气不在同拍反复回流。
- 普通制造机附魔只在实际基础产币上追加 I / II / III 对应收益；不额外耗矿，缺电、缺矿不凭空产币，缺灵气只降低附加部分。按机型记录各附魔等级台数，新机不自动附魔，出售先移除最高级附魔且不退费。
- `save.ts` 保存实体、队列、已固定结果和随机状态、附魔台数 / 优先级、研究投资与高风险暴露。转生仅保留新图鉴，其他新实体与作业回到本轮初态；旧宇宙与星图的继承边界不变。
- 普通污染事件只增加可维护的故障，不减少设备数量。大型硅岩反应堆的高风险开关需明确确认，按实际燃料负载累计暴露；事故只损失该机型一台，不连带库存或其他设备。模式、暴露与重置约束由核心负责。

## 日志与诊断

- 日志仅保存在内存和浏览器本地存储；复制与下载由玩家主动执行，不连接日志服务器。
- 事件统一包含稳定标识、级别、分类、发生时间、游戏时间、打开会话及当时的版本和构建信息。旧记录缺少的版本标为未知，不套用当前版本。
- 关键操作记录实际结果。建造、出售、升级及资源调整保留变化前后值；正常的条件不满足和手动采矿归入默认关闭的调试级别，调试开关只影响本次打开。
- 连续相同事件只在同一会话、相同现场且相邻时合并，保留实际次数和首末时间。容量满后先淘汰低级别的旧记录，全部同级时淘汰最旧记录；上限和合并窗口以 `log.ts` 为准。
- 普通事件延迟批量写入，首次警告和错误立即写入；离线补算期间按拍收集事件，批量通知与写入。隐藏或关闭页面时保存尾部记录。存储失败仍可浏览、复制和下载，并可重试保存。
- 替换核心后同步日志的状态基线；模拟事件使用结算后的游戏时间。离线补算也记录中途完成的研究等关键事件，但不逐拍播放音效。
- 面板支持级别、分类、关键词、最后发生时间和本次会话筛选，按需加载更早记录。TXT 与 JSON 导出始终包含全部留存记录、环境和当前状态，不受筛选或分页限制；不附带存档正文。
- 错误未读提示使用事件序号，清空、轮转和重复合并后仍能发现新错误。异常文本或现场快照读取失败不能阻断记录和报告导出。

规范参考：[游戏日志系统](https://www.edwardrio.com/game-engineering/07-%E6%B8%B8%E6%88%8F%E6%97%A5%E5%BF%97%E7%B3%BB%E7%BB%9F.html)；按本地单机游戏的范围采用分级、结构化、关键操作留痕、批量写入和查询原则。

## 界面与视觉

- 桌面工业控制台：左侧导航与电压等级、横向资源库存（材料与 GT 币各六列）、中部紧凑厂区及工作台、右侧矿脉 / 电能 / 研究 / 污染 / 扩张操作栏。手机同页上下布局，四入口底栏；手机或低高度视口默认收起厂区。
- 主厂区使用 `FactoryScene3D.vue` 与 `scene/factory3d/`，以 Three.js 呈现方块机器，支持旋转、平移、缩放、WASD 和升降；标记及操作保持为真实 DOM 按钮。
- 设备编号从渲染器中的同一相机投影，点击机体使用 Three.js 射线拾取；远景隐藏编号，避免重叠。
- 设备场地按具体机型划分：当前机型的真实已建台数全部放在同一块地板上，切换机型才切换场地。主画面不设上一台 / 下一台或序号输入栏；点击机体或标记选中实例，可通过「靠近所选」观察，不隐藏其他同型机器。`model-layout.ts` 以固定方环顺序追加位置，并按实际占地留一格通道；增加数量不移动已放设备。渲染器只接收当前机型，批量实例化全部台数，不创建其他机型的实例。GT 机型使用本机客户端导出的原生六面材质；多方块保留原结构、占地及控制器，仓口位置使用原结构机壳，不放置输入输出、能源、动力或消声舱室。非 GT 设备使用原模组网格，灵气节点保留原生动态光效。筛选和场地编辑不影响生产。
- 实际设备运行台数来自快照，生产活动仍为类别汇总粒度，待机不播放生产粒子。厂区显示数量不能充当精确到单机的物流结算。
- 鸿蒙之眼运行时在结构中心显示原版宇宙壳、三层恒星和轨道天体；大型蒸汽、燃气、等离子及超临界蒸汽涡轮使用原版 3×3 正面转子。停机后宇宙效果消失、转子切换静态纹理；关闭动态保留当前姿态。专用效果代替这些机型的通用烟雾，网格和材质按部件共享实例批次，远景简化并剔除视野外效果。素材与参数以 `src/assets/factory3d/effects-manifest.json` 为准。
- 原生方块网格以尺寸中心对齐布局原点，底面落在占地范围内的最高地表；控制器、选择框、拾取与专用特效共用同一放置坐标。
- 厂区与设备工作台共享一个选中类别。工作台只渲染当前类别，内容视口高度稳定并在内部滚动；重复点击当前类别不收起，切换不做高度动画。机器本体和名称标记可点击选择并联动工作台类别，选择不滚动页面；购买、停机等操作在工作台完成。切换类别只重置内部列表的滚动位置，不移动整个页面。
- 四个页面首次访问时创建，切换时缓存。工厂保留相机与设备选择，星图保留平移位置，设置保留输入和日志筛选。离开时暂停场景绘制、采矿与星图动画，日志面板取消订阅且不标记新日志已读；返回时同步当前数据。游戏卸载时释放页面与场景资源。
- 厂区折叠同样使用缓存而不销毁相机。设备类别与电压筛选、所选摘要保留；明确管理后才定位工作台。电压突破保留独立入口。
- 奥术管理位于工程科技，不新增主页面。节点和支架每页 24 条，厂区实体节点每页 12 条；详情 / 比较使用查询层，关闭保留列表、选择与页面上下文。工厂额外设施区展示真实安装节点与辅助工程状态。
- 厂区内部像素比为 1；相机操作和通用粒子最多 60 帧/秒，原生纹理动画最多 30 帧/秒，独立光效和多方块特效最多 20 帧/秒。离开可视区域或切后台停止绘制，关闭动态效果后只在交互、尺寸或状态改变时重绘。
- 动态画面开关是独立本地偏好，不进入数值存档；关闭后暂停持续动画，手动采矿保留点击反馈。系统减少动态效果同时关闭持续动画和点击动效。
- 主题颜色与材质以 `tokens.css` 为唯一来源；电压配色以 `src/content/voltages.json` 为准，CSS 变量和素材脚本从中派生。暗钢与原版亮灰复用已有 GT 面板、按钮及插槽贴图，不换成通用蓝绿控制台；经典深色选项保留。数字使用本地字体，不请求远程素材。

方块原型与贴图配方由 `src/content/scene-machines.json` 定义，完整机型名称、类别与图标从内容注册器读取。`state.ts` 保留只读快照中的真实台数，场地直接传入当前机型，不用少量代表设备替代。上述行为同样适用于隔离预览。

机器各面使用 Modernity-GTNH 原始 PNG，将机壳和透明覆盖层合成，动画按原包帧序及 tick 时长播放。提取器为 `scripts/extract-factory3d.py`，逐张路径及机型各面配方以 `src/assets/factory3d/manifest.json` 为准；不借用相似机器贴图。

设备场地默认使用连续的 16×16 区块：外围一格粉红色混凝土，中间 14×14 白色混凝土，边框属于每个区块自身，正负坐标均重复。`ground-view.js` 用一张随相机按区块平移的重复贴图平面覆盖可见范围，移动不累计生成地块。原三层蓝图保留为「预设一」，选择时才创建，结构与来源见 `gtnh3d/README.md`「地板数据与铺设」。设备底面落在占地内的最高地表；「复位视角」查看当前设备，视角通过拖动、WASD 与空格 / Shift 操作；设置页预览提供靠近 / 远离按钮。矿脉动画继续使用现有素材。

场地编辑器可逐格更换地表、添加 / 拆除装饰方块、调整整组设备位置、撤销 / 重做并保存自定义预设。地表层为 -1，装饰高度从 0 起；还原地表恢复当前预设，不删除基础地板。装饰按材质批量绘制，不允许与任何已放置设备实体重叠，通道仍可编辑。应用预设影响当前机型的整块场地，自定义预设保存设计副本。每个机型共享一份场地配置与会话内视角；设备数量变化不复制地板或导入数据。

主画面通过「自定义场地」打开原生「场地设置」弹出页，在页签中切换自定义与导入；尚未建设机器时也能进入导入页签并保存预设。`GroundSettingsDialog.vue` 管理键盘焦点、背景滚动锁和响应式布局；桌面设置与预览并排，手机预览位于设置区上方，表单内部滚动。通过 Teleport 将同一个画布移入弹出页，关闭后移回主画面，不创建第二个渲染器。弹出页显示时保持预览绘制，不受主画面滚动位置的相交检测误判；离开应用页面或切后台仍暂停。Esc、完成按钮及遮罩可关闭，恢复触发按钮焦点和原滚动设置，同时退出铺设模式并取消尚未应用的蓝图预览。

外部场地入口接受 `.schem`、`.schematic` 和 `.litematic`，不接受 JSON 场地。`ground-file.ts` 使用可在浏览器运行的 NBTify 解码，读取 Sponge v1–v3、MCEdit 数字 ID / 元数据 / AddBlocks 与 Litematica 紧凑状态数组；多区域和负尺寸区域保留相对位置。内联 Worker 负责读取，用户可取消；所有数据均留在本机。仅导入方块，忽略实体、容器内容及源世界绝对坐标。文件上限 64 MB、选区上限 200 万格，实际渲染上限 25 万可见面，避免大量离散方块耗尽浏览器资源。

导入先在当前机型场地预览，尚不修改原配置；可取消、保存为新预设或应用到当前机型。`terrain-catalog.ts` 解析支持的方块材质和形状，直楼梯、半砖及透明方块保留对应外观。不能原样显示的方块以粉红线框提示，必须明确选择替换材质或跳过后才能保存 / 应用。`terrain-view.js` 只绘制可见面，并共享材质图集；导入范围以外继续显示默认区块地板。地形与机型均有明确销毁路径，异步读取不会在取消后覆盖当前场地。

场地库由 `useGroundLibrary.ts` 保存在 `storageKey('gtnh-incremental-grounds')`，正式与隔离预览沿用各自作用域。场地是视觉偏好，不参与 GameCore 结算或数值存档；通过编辑器独立导出 / 恢复本游戏的 JSON 备份，此入口与外部蓝图导入分开。导入地形采用调色板和游程编码，机型与预设通过结构 ID 共享数据；没有任何引用的地形随配置保存清理。存储失败显示未保存提示，仍允许导出；无效配置按 `ground.ts` 与 `ground-structure.ts` 清洗。

手动采矿卡片使用 `pickaxe.veinTier` 对应的实际可采矿脉。鼠标落点换算到矿石自身坐标，键盘和文字区点击从矿石中心反馈；系统减少动态效果时不创建粒子，连续点击的粒子数量有界，卸载时取消回调。

资源格显示名称与真实库存，点击后在资源栏内展开收支详情：桌面材料详情在左半边，GT 币详情在右半边，手机全宽显示。支持 Esc 关闭并把焦点返回触发按钮；触屏不依赖悬停。

发电主读数和工作台汇总采用上一模拟拍的实际发电量除以步长；额定能力保留在独立说明和明确标记的明细列中，不冒充实际输出。

## 构建与验证

运行命令和产物以 `status.md` 为准。Web 目录与便携 HTML 使用同一套源码和同一次 Vite 构建。
便携打包不能删除 Web 目录；本地游戏不依赖外部服务器、账号或网络资源。

单元测试覆盖数值与玩法、存档清洗、在线/离线一致性、补算取消、部分存档时间和场景快照适配。
跨模块交互需通过实际浏览器入口验证：采矿、矿石建造、停机恢复、页面导航、主题、存档往返与减少动态效果。
浏览器验证使用独立测试上下文，不读取或覆盖用户正在玩的存档。
真实新档推进与预置实验存档必须分开标注：前者证明原经济可执行到已观测阶段，后者验证高压功能、双端操作与规模；有限阶段或简化估算不能冒充全 MAX 通关。
