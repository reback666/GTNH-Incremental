# 项目现状与后续计划（接手先看这份）

> 最后更新：2026-09-25（第三阶段已完成研究解锁、转生与永久加成、成就与统计、平行宇宙框架 + 工业 / 奥术 / 深渊宇宙，并补齐 UHV~MAX 的发电机、加了日志与反馈；`plan.txt` 为 v3.2）。当前：测试 228 个全绿，单文件产物 513 KB。

> 设计细节以 `plan.txt` 为准，公式以 `src/numeric/` 为准，这份文档不重复它们的数字。

## 1. 项目是什么

GTNH（GregTech: New Horizons）主题的增量 / 放置游戏：从超低压 ULV 起步，沿 14 级电压做到 MAX。
网页实现（Vue 3 + TypeScript + Vite + Pinia），构建成**单个 HTML 文件**，本地私人使用，也可以直接发给朋友玩。

## 2. 怎么跑

| 命令 | 作用 |
| --- | --- |
| `npm test` | 跑全部单元 / 集成测试（vitest） |
| `npm run build` | `vue-tsc` + `vite build` + 内联成单文件，产物在 `dist/GTNH增量.html` |
| `npm run dev` | 开发服务器（改代码即时预览） |
| `npm run balance` | 重算 `docs/balance.md` |
| `python scripts/build-veins.py` | 重新生成矿脉贴图与 `src/game/vein-meta.ts` |
| `python scripts/build-facility-icons.py` | 重新生成存电装置 / 净化器 / 计算机 / 研究站图标 |

后两个贴图脚本需要本机的 GTNH 开发包（Gradle 缓存里的 `GT5-Unofficial-*-dev.jar`）
和原版 1.7.10 客户端 `client.jar`，缺失时脚本会直接报错说明。

## 4. 已经做完的

**第一阶段（核心原型）**：ULV→LV 完整循环、手动挖矿、14 级电压 / 矿石 / GT 币数据结构、
采矿机 + 发电机 + 制造机、T0 矿脉 MVP、科技树与基础 UI、成本与产出公式。

**第二阶段（自动化与深度）**：

- 矿脉分级：等级 n 的采矿机采 T(n-1) 矿脉，矿脉按等级产出多矿种
- 超频档位 0-3（每档速度 +60%、耗电翻倍，只给采矿机与制造机）
- 故障与手动维护（超频换来的风险，坏掉的机器不产不耗）
- 存电装置（MV 起，富余充电 / 缺口放电 / 放完降载）
- 污染机制（三档效果 + 变异奖励 + 工厂崩溃，设置里可整套开关）
- 净化器（MV 起，压污染）
- 电网四种：普通（开局，偶尔断电）/ 稳定（LV 解锁，+8% 耗电不失电）/
  波动（MV 解锁，-10% 耗电但常断电）/ 黑市（HV 解锁，-15% 耗电但会被偷币）；
  解锁要花**对应等级的 GT 币**
- 数值模拟（`docs/balance.md`）与整体平衡
- 产矿节奏：采矿机在 GTNH 基准上整体提速 **8 倍**（耗时 ÷8、耗电不变，见 `MINER_OUTPUT_FACTOR`），
  所以矿石是宽裕资源；每台采矿机稳定能养约 5-7 台同级发电机

**镐子（手动开采的升级线）**：

- 手动挖矿改成「手动版采矿机」：作用在当前挖得动的矿脉上，产量按矿脉规则均分给它的全部矿种
- **「镐子」是机器面板标签行里的第一个标签**（排在采矿机前面），点开向下列出三条线
  （金刚杵 / 连锁采集 / 连锁爆破），每行一条：图标 + 效果 + 进度 + 升级按钮，标签角标写着还剩几次能升
- 三条线各有自己的工具图标（金刚杵取自 GT 的 `gt.Tool_Vajra.png`、连锁采集用 IC2 的电动钻头、
  连锁爆破用 IC2 的炸药），都按 14 级电压上色、颜色跟着各自进度走
  （`python scripts/build-pickaxe-icons.py`，预览图 `docs/pickaxe-tiers.png`）
- 三条升级线（公式见 `src/numeric/pickaxe.ts`，设计见 `plan.txt` 第四章）：
  金刚杵每电压 1 次、每次多挖一级矿脉；连锁采集每 2 个电压 1 次、每次产出 ×2；
  连锁爆破每电压 2 次、每次 +2^(n/2)（n = 这次机会产生时的电压等级，加值当场定死，
  之后升电压不会变；所以逐级点掉与攒到最后点掉结果相同）
- 产量 =（基础 1 枚 + 连锁爆破加值）× 连锁采集倍率，界面在第 1 页矿脉面板里
- 存档升到 v13（三条线的进度）

**界面**：主界面分三页，右侧竖排页码按钮换页（当前页放大点亮，换页有淡出淡入过渡）——
第 1 页工厂（资源条：电能四格 + 点击下拉明细、矿石、GT 币、研究进度、标题栏带构建时间；
矿脉面板：点击挖矿 + 全套反馈特效；机器面板：6 类折叠标签、超频档位、故障维护、批量购买、
悬停看单台数值），第 2 页科技（科技树、电网、转生入口），第 3 页设置（污染开关与读数、
开发者模式、存档、日志）。

第 3 页的**开发者模式**默认关闭，打开后才露出测试用的快捷操作：解锁到指定电压
（同时开放矿脉、把该级及以前标记成已研究）、每级矿石与 GT 币各加一笔、送时空线缆、
快进 1 分钟 / 10 分钟 / 1 小时、清空全部机器，外加一排内部状态读数。
关掉开关就全部收起；关闭状态下调用这些操作会被核心层直接拒绝。

机器面板的标签**按进度出现**：研究类要到 LuV 才出现、灵气节点要有奥术宇宙才出现；
资源条上的「研究」区同样到 LuV 才显示。没到那一步的类别整个不占位置。

机器面板的标签**悬停会列出一类机器吃到的全部增益与减益**（`modifierRows`）：
每行写「作用 / 数值 / 来源」，例如「速度 +12% 转生·加成树」「耗电 +8% 电网·稳定」
「产出 -20% 污染」「产量（魔法机器）+30% 奥术宇宙·灵气充裕度 100%」，另有超频与故障的汇总。
镐子标签列出的是它自己那三条升级线的当前效果。

**贴图与特效**：机器与设施图标由 GT 贴图合成（机壳 + 面片）；
矿脉用原版矿石贴图，无尽 / 宇宙中子素 / 龙芯 / 时空带原版动画帧与特殊渲染光晕；
挖矿反馈包含下沉回弹、柔光、落点星芒、矿脉正中 40×40 的裂纹（原版 10 级破坏贴图）与石屑。
机器图标的机壳**按电压染色**（`scripts/gtnh_tiers.py`，取自 wiki「电力」页的官方配色），
所以 14 级机器的颜色差别明显；两套图标脚本都会染色，另有测试盯着「每个机型都有 32×32 图标」
与「14 级采矿机 / 制造机图标两两不同」。

**存档**：v12 + v1→v12 迁移；大数值一律十进制字符串存 JSON。

**日志与反馈**（`src/game/log.ts`、`src/game/diagnostics.ts`、`src/components/LogPanel.vue`）：
设置页底部一块「日志」，玩家遇到说不清楚的问题时点「复制日志」把内容发给作者：

- 导出的是纯文本，含环境信息（版本、浏览器、打开方式、屏幕、语言）、导出那一刻的厂况快照
  （电压、周目、电网与污染、已研究、每种机型台数、资源、上一拍读数）与事件记录
- 浏览器不让自动复制时（`file://` 常见）改用文本框手动复制，也可以直接下载成 txt
- 自动记录的事件：启动、存档读 / 写失败、模拟运算出错（带现场快照）、未捕获的异常与异步错误、
  界面渲染出错、污染档次变化、断电降载与恢复、工厂崩溃、电压解锁、研究完成、时空裂缝、转生、导出日志
- 出现错误记录时「设置」页的页码按钮亮一个小红点，翻到该页即消失
- 模拟连续崩 5 拍自动暂停（避免每秒刷一条日志），界面提示导出日志后刷新页面重来
- 日志只落在本地 localStorage（与存档分开，重开一局不清），上限 300 条，**任何情况下都不自动发送**

**第三阶段第 5 块（奥术宇宙）**：

- 新增类别「灵气节点」（`n-<等级>`，1~14 级）：只有拥有奥术宇宙才能建造（界面挂「需奥术宇宙」）
- 新增**魔法机器**：魔法采矿机 / 魔法发电机 / 魔法制造机混在原来的三类里（`mm-` / `mg-` / `mc-`，
  LV~LuV，ZPM 及以后没有）。它们不耗电、改吃灵气，成本系数与电力版相同，产能是同级电力机器的 **2.5 倍**；
  图标是同级面片配紫色机壳，机型名后挂「魔法」徽章
- 灵气是流量：节点产灵气，只有魔法机器吃它（普通机器照常吃电，发电机与存电装置照常工作）
- 灵气充裕度（喂上的灵气 ÷ 魔法机器要的灵气）决定产量加成：普通机器最多 **+10%**、
  魔法机器最多 **+30%**；没有魔法机器时不加成（旧的「全厂产量 -50%」已删除）
- 魔法机器故障率归零（灵气驱动），可以放心拉满超频
- 源质：净化器压污染时副产（每 1%/秒的净化产能 → 1000 源质），灵气节点满负荷每秒吃 1 源质；
  源质不够时节点按比例降出力，最低仍有 50%（所以不会因为污染为 0 就停摆）
- 奥术宇宙**不吃**「污染驱动产出」：污染在这里仍然按普通规则惩罚产出，
  净化器的作用很单纯（给源质养节点 + 压惩罚）
- 资源条在奥术宇宙下多一块「灵气」区（产出 / 魔法机器消耗 / 充裕度 / 产量加成 / 源质存量与净变化）
- 灵气节点图标是自己画的灵气结晶叠在机壳上（GT 里没有对应机器）
- 存档升到 v11（源质存量）

**第三阶段第 6 块（深渊宇宙）**：

- 污染从惩罚变成燃料：30% 中性，每低 1 点 -1%、每高 1 点 +1%（与奥术宇宙共用同一条倍率，
  两个宇宙都拥有时只算一次）
- 代价：污染**腐蚀机器** —— 每台每秒的损坏概率 = max(0, 污染 − 30 − 抑制点数) × 0.000005，
  坏掉的机器停机、要手动维护（发电机与净化器同样会被腐蚀）
- 新增类别「腐蚀抑制器」（`s-<等级>`，1~14 级，只有深渊宇宙能造）：按等级抵消污染点数
  （tier × 5 点）
- 污染条上的说明文案会跟着变：有奥术 / 深渊宇宙时写「产出 +40%（30% 是中性点）」，
  不再写普通宇宙那套「产出 -40%」
- 存档升到 v12（下次转生要带的平行宇宙选择）

- 研究解锁的粒度：当前按电压等级解锁（一次开放该级全部机型），要不要细到逐机型
- 制造机是否分成多种机型（省矿 / 速度 / 成本取舍）
- 矿脉产出比例：多矿种均匀（当前实现）还是按等级递减
- 多方块的取舍：现在多方块只有好处、没有缺点机制（原先挂的「不按需发电 / 需要维护」
  两条标注是假的，已去掉），要不要给它加真实代价
- 镐子的强度：连锁爆破用 2^(n/2) 后，一次点击全程等于同级采矿机跑 13~27 秒（见 `docs/balance.md` 2.5），
  手感是否合适，还要不要继续调

另外还有一处实现问题要修：电网解锁价现在恒等于该等级的 5000 枚币，已定为「该等级首台机器价 ×16」（见计划书第六章）。

## 7. 约定与踩过的坑

**工作流**

- 一次改动 = 一个可回退的提交。流程固定：`npm test` → `npm run build` → `git commit`。
- 提交信息用中文，写清「改了什么、为什么」。
- **未经用户同意不要修改 `plan.txt`**（用户明确要求过）。
- 面向用户的文字全用简体中文；命令不能用 PowerShell 5.1，要能处理中文路径。

**数值**

- 所有累计运算走 `Decimal`（40 位精度），禁止二进制浮点参与。
- 存档里数值存十进制字符串：`JSON.parse` 只有 double，超过 2^53 在解析阶段就丢精度，
  事后转 Decimal 也救不回来。

**打包**

- `scripts/inline-dist.ts` 内联后会删掉 `dist/assets`，所以贴图必须内联成 data URL
  （`vite.config.ts` 已把 `assetsInlineLimit` 提到 4 MB）。超过阈值的图会变成打不开的外部文件。

**贴图与动画**

- 动画帧是**竖排条带**（宽 = 单帧，高 = 帧数 × 单帧），CSS 用 `steps(帧数)` + `translateY(-100%)` 播放。
- 条带容器必须 `overflow: hidden`：曾经因为少了这一句，40×40 的碎裂纹被画成 400px 的长条。
- 贴图文件名必须等于机型 id / `vein-meta` 的键，否则界面找不到图（曾经裂纹图因此完全不显示）。
- 机器面板的标签顺序与「按 id 找机型」共用同一份清单（`src/game/store.ts` 的 `COLUMN_ORDER`）：
  曾经各写一份，加净化器时漏在查表那边，结果是按钮能点但买不到。

**验收视觉改动**

- 用 Playwright + 本地 Chrome 抓帧，量「变化像素的包围盒 / 亮度峰值」这类可量化的事实，
  不要只看元素尺寸（曾经只看元素框，没发现溢出）。
- 截图 / 抓帧脚本写成 `scripts/.xxx.mjs` 这种临时文件，用完删除；`%TEMP%` 里的临时目录也一并清掉。

**模型看不到图片**

- 助手无法直接查看图片，视觉结论必须来自量化测量 + 用户验收；
  每次改完视觉都出一张预览图（`docs/*.png` / `*.gif`）让用户点头。
