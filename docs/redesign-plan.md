# 基于 dev 的玩法与画面实施计划

## 适用范围与实施基线

本计划以本地 `dev` 分支的现有系统为基础。现行玩法以 `game-rules.md` 和 `../src/game/`、`../src/numeric/`、`../src/content/` 的实际实现为准，实施状态见本文执行表，运行方式见 `status.md`。

保留原有循环：**手动或自动采矿积攒矿石 → 发电机消耗矿石供电 → 制造机消耗矿石与电力产出 GT 币 → 扩建与解锁电压。** 矿石有真实库存；发电与制造会实际扣矿；库存可以支持没有正在运行的采矿机的工厂。

货币等级、矿脉分配、机型、镐子、能源、研究、宇宙、转生和存档沿用 dev，不以界面重做为由合并币种、删除资源或另造生产公式。用户明确确认的定向改动单独实施；建议不等于已经获准替换现有系统。

独立预览入口 `demo.html` 直接使用现有 `src/main.ts`、`App.vue`、GameCore、store 与页面组件。预览不维护另一套经济模型；通过入口声明的存储范围隔离本地存档、时间戳、主题、界面偏好、日志与动态效果偏好。正式入口存储键不变，旧演示存档不自动转换。

## 已确认方向

### 原有系统与成长

- 采矿与制造维持原有分工，不能把手动采矿改为直接得 GT 币，也不能把矿石库存改为不可积存的供给速率。
- 各级矿脉、矿石、GT 币、设备价格、燃料效率与制造耗矿先沿用 dev 参数；不直接合并原有余额或照搬废弃演示的参数。
- 数量扩张仍是重要反馈；升级阶段不自动报废旧设备，玩家可以保留、扩建或替换。
- 手动起步与挂机结合，自动化后不要求持续点击；回归后能看懂库存、收益与瓶颈。
- 每阶段增加代表工程与清晰目标的方向保留，但不能擅自改掉原有电压解锁条件。目标可关闭。
- 首次自动采矿约五分钟、首轮现实时间三到七天是后续节奏目标，须在 dev 体系上重新验证，不能使用其他生产模型的路线作为证据。

### 画面与操作

- 电脑与手机均完整可玩。桌面左侧控制中心、中间设备场地和工作台、右侧开采与能源等操作栏。
- 手机同页上下排列，厂区可折叠，底部保留工厂、工程科技、星图、设置四个入口；不把电脑三栏缩小搬上手机。
- 资源区保留实际矿石与各级币库存，点击可查产出、消耗与净变化；不通过隐藏资源改变玩法。
- 控制中心与面板沿用所选主题材质，时代通过设备与局部反馈呈现，不强制换主题。
- 机器图标使用启用 Modernity 后的 GTNH 原生完整物品栏图标，素材依据见 `../scripts/texture-sources.md`；不以自绘或拼接冒充。
- 每个机型独立场地，同型号全部机器放在一起；支持观察、定位、旋转、平移、缩放、复位、地板编辑和蓝图导入，位置不影响产能，不要求手动接线铺管。
- 后期保留上千台真实设备的同型批量呈现、定位与管理，支持机型、类别与阶段筛选。
- 点击设备选中并联动工作台类别，不自动滚动页面；查询关闭后保留选择、视角与工作台位置。
- 当前阶段展开，旧阶段折叠但保留收益和异常摘要；关键建设与突破加强反馈，并提供减少动态效果选项。

以下定向改动已接入原应用，正式与隔离预览共用实现；逐项验收及未完成范围见执行表。

| 内容 | 已确认要求 | 实施边界 |

| 污染 | 降低前期排放；具备处理能力时污染显著增加 | 净化器开放前排放为原值 5%，开放后恢复原值；保留原污染与净化系统 |

## 当前检查点与后续起点

当前交付为 **基于 dev 原体系的共用正式应用与隔离预览**，入口、产物和验证记录见 `status.md`。没有建立另一套单币经济；用户确认的污染、研究、安全和离线改动已落地。

七日实跑已经结束，工业停止现场、目标差距和策略限制以 `balance.md` 为准；完整实证保留在 `../outputs/balance/progression-7d-seed-20261024.json`，可续跑存档在 `../outputs/balance/progression-checkpoint.json`。后续从该存档及随机状态继续 P4.3，增大累计模拟天数，不重开已观测前段；操作命令见平衡报告。原价格与产量不为迎合目标被强改，当前结果不能证明最优路线或完整终点。奥术以同预算报告为依据验证备用节点培养、高质量 / 高压、附魔等场景，并补齐四类辅助设施原生素材；不得把一个低压场景或预置实验资产写成全面平衡 / 从零通关完成。
